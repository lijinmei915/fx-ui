# Agent UI 视觉规范

> 用途：定义 Agent UI 在 fx-ui 里的独立视觉方向。
> 不要写什么：业务接口、Agent 提示词、底层通信协议。

---

## 一句话

Agent UI 的视觉可以参考好看的 C 端体验，但不能另起一套设计系统。

```txt
视觉气质参考 C 端
底层能力仍用 fx-ui
```

也就是说：

- 可以更轻、更顺、更像对话里的结果卡。
- 不能自己发明一套颜色、按钮、圆角、阴影和组件库。
- 所有视觉仍然通过 `theme/fx-theme.css`、shadcn 基础组件和 `src/components/fx` 组合组件落地。

## 参考方向

| 参考 | 借鉴什么 | 不照搬什么 |
|------|----------|------------|
| C 端 AI 产品 | 对话流里的轻量结果块、简洁操作、低噪音信息层级 | 不照搬具体品牌皮肤、渐变、动效和营销感 |
| Microsoft Adaptive Cards | 卡片结构、字段、行动按钮和宿主内渲染边界 | 不照搬 Teams/Copilot 的完整 schema 和平台样式 |
| Material Cards | 一个卡片承载一个对象或主题，内容边界清楚 | 不把后台整页、复杂表格或大表单塞进卡片 |
| Apple HIG / C 端卡片 | 留白、层级、直接、少即是多 | 不为了高级感牺牲可读性和操作确定性 |
| shadcn/ui | Card、Button、Badge 等可组合基础件 | 不在 Agent UI 里重写基础组件 |

## 视觉原则

1. **像对话里的结果块，不像后台页面。**
   Agent 卡片应该轻量、聚焦、可快速扫读。

2. **一个卡片只表达一件事。**
   一个对象、一个文件、一个结论、一个操作组。不要把完整工作台塞进卡片。

3. **先结论，再依据，再行动。**
   用户先看懂 Agent 想说什么，再看为什么，最后决定点什么。

4. **主操作最多一个。**
   一张卡片里主按钮最多 1 个，次按钮最多 2 个。更多操作进入详情或二级菜单。

5. **证据列表最多 3 条。**
   Agent 给依据是为了建立信任，不是把推理过程全摊开。

6. **状态要克制。**
   普通状态用弱化文字和 Badge；危险动作使用 `destructive`，并进入确认流程。

7. **不做卡片套卡片。**
   卡片内部可以有字段、列表、操作，但不要再嵌套另一个完整 Card。

8. **多块结果优先收成一个连续 Surface。**
   对象、文件、洞察、操作连续出现时，用一个外层结果面板承载，内部用分隔线和浅底信息块区分层级；避免把多个大卡片垂直摞开。

9. **不放完整表单。**
   Agent 卡片可以承载确认、选择、轻输入；复杂表单打开详情页、Sheet 或 Dialog。

## 密度规则

| 项目 | 规则 |
|------|------|
| 卡片宽度 | 跟随宿主容器，不写固定宽度 |
| 卡片内边距 | 使用 Card 默认结构，不单独覆盖基础 padding |
| 标题 | 一行优先，必要时自然换行 |
| 摘要 | 1 到 2 句 |
| 字段 | 4 到 6 个以内 |
| 证据 | 3 条以内 |
| 操作 | 主操作 1 个，次操作最多 2 个 |
| 多卡片 | 垂直排列，保持同一层级，不做复杂网格 |

## 卡片类型视觉

| block | 视觉重点 | 注意 |
|-------|----------|------|
| `object-card` | 字段清楚，像一张对象摘要 | 字段过多时进入详情 |
| `file-card` | 像附件行一样紧凑，文件名、类型、摘要优先 | 不显示长路径和复杂权限 |
| `insight-card` | 结论、依据、下一步，依据用短字段承载 | 不把长篇分析塞进 summary |
| `action-row` | 让用户快速选择下一步 | 不让按钮看起来像在执行未知代码 |

## C 端感怎么落地

可以借鉴：

- 更短的标题。
- 更温和的辅助文案。
- 更清楚的主次按钮。
- 更少的边框噪音。
- 更明确的对象、文件、结论分组。
- 更少的字段和更强的信息筛选。

不可以借鉴：

- 随意渐变。
- 大面积品牌色背景。
- 装饰性动效。
- 多层卡片套娃。
- 用图标和颜色替代文字说明。
- 把消费级营销页的视觉直接搬进企业 Agent。

## 和 fx-ui 的关系

Agent UI 是 fx-ui 的视觉子系统，不是新组件库。

```txt
fx-ui token
  -> shadcn 基础组件
  -> src/components/fx 组合组件
  -> Agent UI 卡片规范
```

修改 Agent UI 样式时，优先级是：

1. 先看 `docs/AGENT_UI_VISUAL.md` 是否已有规则。
2. 再看 `docs/AGENT_UI.md` 是否允许这个 block 或 action。
3. 再看 `src/components/fx/agent-surface.tsx` 是否支持。
4. 如果只是局部布局，改 className。
5. 如果是全局视觉语言，回到 token 或组件规则，不要在 Agent UI 里硬编码。
